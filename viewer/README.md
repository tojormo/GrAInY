# 圃場写真ビューワー (KSAS Field Photo Viewer)

GitHub Pages 上で公開する、圃場写真を地図から検索・閲覧するための静的サイトです。
`/img/` フォルダに大量の写真を保存していく運用を想定し、**JSON にある圃場のうち、
実際に写真が存在するものだけ**を地図上のピンとして表示します。

## 1. 構成

```
リポジトリのルート (またはGitHub Pages公開フォルダ)
├── index.html              ← ビューワー本体
├── KSAS_field_all.json      ← 圃場データ(緯度経度・圃場名など)
├── css/
│   └── style.css
├── js/
│   └── app.js               ← 設定・ロジックはすべてここ
└── img/
    ├── 20260920_082945_Hosokawa_３０２_FieldHigh.jpg
    ├── 20260919_070000_Katayama_１６４_FieldWide.jpg
    └── ...(写真を追加していくだけでOK)
```

`index.html` ・`KSAS_field_all.json` ・`img/` は**同じ階層**に置いてください。

## 2. 写真のファイル名ルール

```
日付_時間_撮影者_圃場ID_撮影種別.拡張子
例) 20260920_082945_Hosokawa_３０２_FieldHigh.jpg
```

| 項目 | 例 | 説明 |
|---|---|---|
| 日付 | `20260920` | YYYYMMDD (8桁) |
| 時間 | `082945` | HHMMSS (6桁) |
| 撮影者 | `Hosokawa` | アンダースコアを含めないこと |
| 圃場ID | `３０２` | `KSAS_field_all.json` の `圃場名` と対応 (全角/半角の違いは自動で吸収されます) |
| 撮影種別 | `FieldHigh` | 任意の文字列 (例: FieldHigh, FieldWide, Disease など) |

対応拡張子: `.jpg` `.jpeg` `.png` `.gif` `.webp`

この形式に合わない、または `圃場名` と一致しないファイルは自動的にスキップされ、
右上の件数表示で「命名規則エラー」「圃場未一致」として確認できます。

## 3. 画像一覧の取得方法(自動)

このビューワーは img フォルダの中身を **サーバー無しで** 検出するために、
以下の優先順位で画像一覧を取得します。

1. **`img/manifest.json`** が存在すればそれを使用 (任意・オプション)
2. ブラウザのセッションキャッシュ (直近 10分以内に取得済みなら再利用)
3. **GitHub API** (`git/trees` recursive) でリポジトリの `img/` 配下を自動取得

通常は 3. の GitHub API 自動取得だけで動作します。GitHub Pages を公開している
リポジトリが **Public** であれば、認証なしでそのまま利用できます。

### manifest.json を使う場面
- 画像枚数が非常に多く GitHub API のレスポンスが重い/不安定
- API のレート制限 (未認証: 60回/時/IP) を避けたい
- リポジトリを Private にしていて API から一覧取得できない

`img/manifest.example.json` に形式のサンプルがあります。CI (GitHub Actions) で
`img/` の一覧を書き出すジョブを組み込むと自動運用できます。

## 4. 設定 (js/app.js 冒頭の `CONFIG`)

GitHub のユーザー名・リポジトリ名は URL から自動判定されますが、
うまく判定できない場合は `js/app.js` 冒頭を直接書き換えてください。

```js
const CONFIG = {
  owner: null,        // 例: "hosokawa"  (nullなら自動判定)
  repo: null,          // 例: "field-photos" (nullなら自動判定)
  branches: ["main", "master", "gh-pages"],
  imgDir: "img",
  jsonPath: "./KSAS_field_all.json",
  manifestPath: "./img/manifest.json",
  cacheMinutes: 10,
};
```

## 5. 使い方

- 検索ボックス: 圃場名・住所・担当者・作付品種で絞り込み
- 地図のピン(📷マーク): クリックでポップアップ→「すべての写真を見る」で一覧表示
- 左サイドバー: 写真がある圃場の一覧。クリックで地図が該当圃場に移動
- 🔄更新ボタン: キャッシュを破棄して画像一覧を再取得(新しい写真を追加した直後に利用)
- 写真クリックで拡大表示(←→キー・画面端の矢印で前後の写真に移動、Escで閉じる)

## 6. GitHub Pages への公開手順(概要)

1. このフォルダの中身をリポジトリ直下にコミット・push
2. `img/` フォルダに写真を命名規則に沿って追加していく
3. GitHub リポジトリの Settings → Pages で公開ブランチを設定
4. 公開URL (`https://<ユーザー名>.github.io/<リポジトリ名>/`) にアクセス

## 7. 既知の制約

- 圃場名が完全に重複している場合、同名のすべての圃場に同じ写真が紐付きます
  (JSON側の `圃場名` は正規化後 318件すべて一意であることを確認済みです)。
- サムネイルはオリジナル画像をそのまま縮小表示しているため、写真の解像度が
  非常に大きい場合は表示が重くなることがあります。必要であれば別途サムネイル
  生成処理(CI等)の追加をご検討ください。
- GitHub API は未認証時 60回/時/IP の制限があります。通常利用では
  セッションキャッシュ(10分)により問題になりませんが、頻繁な更新確認が
  必要な場合は `manifest.json` の利用を推奨します。

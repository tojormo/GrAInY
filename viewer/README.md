# 圃場写真ビューワー (KSAS Field Photo Viewer)

GitHub Pages で公開する、圃場写真を確認するための静的サイトです。
GitHub Actions などのビルド処理は使用せず、**ファイルを置くだけ**で動作します。
`/img/` に写真を追加していくだけで、**メニューバーから2つの見方**で写真を閲覧できます。

## 画面構成

| メニュー | 内容 |
|---|---|
| 🗺️ **地図から見る** | `KSAS_field_all.json` の**全圃場**をピン表示。タップするとその圃場の写真一式(最大5枚)を表示。写真が無い圃場も表示され、その場合は「写真: なし」と表示されます |
| 🏷️ **撮影種別から見る** | 撮影種別(ドロップダウン)を選択 → 該当写真を一覧表示 → タップで地図上の位置にジャンプ |

地図上のピンは、写真の有無で色分けされます。
- 🟢 緑色の📷ピン: 写真あり
- ⚪ グレーのピン: 写真なし(圃場自体はJSONにある全件が表示されます)

## 1. 構成

```
リポジトリのルート (GitHub Pages公開フォルダ)
├── index.html
├── KSAS_field_all.json      ← 圃場データ(緯度経度・圃場名など、全件)
├── css/style.css
├── js/app.js                 ← 設定・ロジックはすべてここ
└── img/
    ├── 20260920_082945_Hosokawa_３０２_FieldHigh.jpg
    ├── 20260920_083000_Hosokawa_３０２_FieldWide.jpg
    └── ...(写真を追加していくだけでOK)
```

`index.html`・`KSAS_field_all.json`・`img/` は**同じ階層**に置いてください。
ビルドやワークフローの実行は不要です。ファイルを置いて GitHub Pages を
有効にするだけで公開できます。

## 2. 写真のファイル名ルール

```
日付_時間_撮影者_圃場ID_撮影種別.拡張子
例) 20260920_082945_Hosokawa_３０２_FieldHigh.jpg
```

- 圃場ID は `KSAS_field_all.json` の `圃場名` と対応(全角/半角の違いは自動吸収)
- 撮影種別 は自由な文字列(例: FieldHigh, FieldWide, Disease, Soil など)。
  ここに入力した値がそのまま「撮影種別から見る」のドロップダウンに反映されます。
- 対応拡張子: `.jpg` `.jpeg` `.png` `.gif` `.webp`
- 命名規則に合わない、または `圃場名` と一致しないファイルは自動的にスキップされます
  (右上のステータス表示で件数を確認できます)。
- **写真が1枚も無い圃場も地図には表示されます**(グレーのピン、ポップアップには
  「写真: なし」と表示)。

## 3. 画像一覧の取得方法

1. **`img/manifest.json`** があれば最優先で使用(任意・手動作成でOK)
2. ブラウザのセッションキャッシュ(10分以内なら再利用)
3. **GitHub API** (`git/trees` recursive) で `img/` 配下を自動取得(標準の方法)

通常は 3. の GitHub API 自動取得のみで動作します(リポジトリが **Public** であれば
認証不要)。ビルド処理は挟まないため、写真を `img/` に追加して push するだけで、
次回アクセス時に反映されます。

### ⚠ 「GitHub APIエラー (403)」が出る場合

GitHub API には **未認証で60回/時間/IP** という利用回数制限があり、これを超えると
403 エラーになります。また、リポジトリが Private の場合も 403 になります。

- **制限超過の場合**: 表示された時刻以降に自動的に解消されます。しばらく待って
  「更新」やページの再読み込みをお試しください。
- **恒久的に回避したい場合**: `img/manifest.json` を手動で作成し `img/` に置くと、
  API を使わずに画像一覧を読み込めます。中身は画像ファイル名の配列です。

```json
{
  "files": [
    "20260920_082945_Hosokawa_３０２_FieldHigh.jpg",
    "20260919_070000_Katayama_１６４_FieldWide.jpg"
  ]
}
```

写真を追加するたびにこのファイルも手動で更新してください
(自動生成は行いません = GitHub Actions 不使用のため)。

## 4. 設定 (js/app.js 冒頭の `CONFIG`)

GitHubのユーザー名・リポジトリ名はURLから自動判定されます。判定できない場合のみ
`js/app.js` 冒頭を書き換えてください。

```js
const CONFIG = {
  owner: null,   // 例: "hosokawa" (nullなら自動判定)
  repo: null,    // 例: "field-photos" (nullなら自動判定)
  branches: ["main", "master", "gh-pages"],
  imgDir: "img",
  jsonPath: "./KSAS_field_all.json",
  manifestPath: "./img/manifest.json",
  cacheMinutes: 10,
};
```

## 5. GitHub Pages への公開手順

1. このフォルダの中身をリポジトリ直下にコミット・push
2. `img/` に写真を命名規則に沿って追加
3. GitHub リポジトリの Settings → Pages で公開ブランチを設定
4. 公開URL (`https://<ユーザー名>.github.io/<リポジトリ名>/`) にアクセス

## 6. 既知の制約

- 圃場名が重複している場合、同名のすべての圃場に同じ写真が紐付きます
  (提供データでは正規化後 318件すべて一意であることを確認済みです)。
- GitHub API は未認証時 60回/時/IP の制限があります。頻繁に確認する場合は
  `img/manifest.json` の手動作成を推奨します。
